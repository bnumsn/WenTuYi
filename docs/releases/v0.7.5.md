# v0.7.5：身份认证、解密结果与桌面收发修复

Android 版本码为 **16**。正常 WTY4/WTY5 密文格式与会话密钥派生保持兼容。

## 修复

- 身份校验由旧 8 位数字升级为完整 256 bit 安全码，确认时重新核对当前身份与联系人，旧验证状态不能沿用。
- Android 密图插入遭宿主拒绝后转分享，分享成功时保持聊天框原文已清除；仅全部交付失败才恢复原文，并保留宿主期间的新编辑。
- 扫描页旋转及键盘切换输入框后保留已消费 WTY5 消息的进程内结果；结果绑定原目标，防止误写到其他输入框。屏幕解密使用带请求标识的单次结果存储，处理中的请求不会因等待超时丢失完成结果。
- 二维码逐页生成、保存和回收，修复密集二维码的伪定位点漏读；多个不同候选明确报歧义。解密图片缓存到期清理，读取时也拒绝过期文件。
- 桌面会话使用跨进程锁和原子持久化，绑定双方身份，保存失败不输出结果；会话重置 epoch 严格递增，兼容同毫秒重置和时钟回退。
- Windows 发送保留完整密文，热键支持联系人，UTF-8 口令及中文正文正确传递；修复 PowerShell 5.1 / .NET Framework 管道自动插入或吞掉 BOM 的问题，保留正文首字符并恢复宿主编码设置。桌面 stdin 保留正文空白与换行，解密 stdout 不额外补换行；Linux 通过 stdin 交给 `xdotool`，避免解密明文出现在子进程参数中。
- 统一收发大小限制与 Argon2 内存、工作量预算；资源不足时拒绝操作，不降低正常 KDF 强度。损坏身份拒绝使用，不静默生成替代身份，提供明确的备份恢复和联系人重建入口。

## 升级注意

- 双方需使用支持完整安全码的版本，通过当面、电话等可信渠道核对**全部 16 组、64 个十六进制字符**；旧 8 位校验及旧验证标记不再作为认证依据。桌面先执行 `peer-verify --peer NAME --code '完整安全码'`。
- 旧桌面状态没有双方身份绑定，需重置：profile 在重新验证后执行 `peer-reset --peer NAME`；原始 `--state FILE` 用原身份及对方公钥重新 `ratchet-init`。双方都需要升级旧状态时，先各自重置，再由最后重置的一方先发新消息；旧会话中未接收的消息可能无法解密。
- 身份不可读时请显式恢复有效备份或重新生成身份。恢复不同身份会清空旧会话并撤销联系人验证；联系人也不可读时可显式清空重建。同一身份且数据可读的恢复保留已有状态。身份备份不包含棘轮会话。
- 聊天框内转换仍无法撤回宿主已读到的原文；需在交给聊天应用前加密时，应在文图易独立输入页直接输入并分享密文。解密结果仅保存在进程内存，不提供永久消息历史。

## 验证范围

API 34 模拟器已通过 **93 项自动化测试及 11 项 UI 验证**，覆盖验证迁移与损坏恢复、棘轮持久化、旋转和输入目标切换、图片分享回退、32 页二维码、密集二维码与 JPEG 解码回归。

发布须通过仓库 CI 门禁，本地结果不等于 CI 已通过。Windows CI 门禁覆盖真实 OS 上的 PowerShell 5.1/7 CLI 与桥接自动化，桌面热键和真实窗口交互仍待验收；真实 Android 设备、真实摄像头与第三方聊天宿主兼容性仍未完成验收。
