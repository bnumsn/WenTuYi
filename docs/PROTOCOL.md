# 文图易 协议规范 (WTY)

跨平台实现者对照文档。权威协议实现为 `shared-protocol`（纯 JVM），Android `app` 与桌面 CLI 复用它，并分别实现本地状态管理。本文对应 v0.7.4（Android 版本码 15）；正常消息线上格式保持不变，身份认证与桌面本地状态迁移见 [README 升级说明](../README.md#v074-安全修复与升级说明)。所有线上格式为 **ASCII 文本**，可经 IM 文本框 / 二维码传输。

## 0. 通用原语

| 用途 | 算法 |
|---|---|
| AEAD | AES-256-GCM，128-bit tag，12 字节 IV；WTY1–4 随机生成，WTY5 从单次消息密钥派生 |
| 口令 KDF | Argon2id（ARGON2_VERSION_13） |
| 旧口令 KDF | PBKDF2-HmacSHA256，120000 次（仅 v1/v2 解密） |
| HKDF | HKDF-SHA256 |
| 非对称 | X25519（RFC 7748），拒绝全零（低阶点）共享密钥 |
| 文本编码 | 载荷 = `前缀` + Base64(标准字母表, 无换行)；身份/备份用 RFC4648 Base32(无填充) |

所有密文载荷形如 `<PREFIX><base64>`，前缀含冒号：`WTY1:` `WTY2:` `WTY3:` `WTY4:`，棘轮为 `WTY5:`。

`type` 字节：`1`=文本 `2`=图像 `3`=分页图像(`WTYIPG1`magic+pageNo+pageTotal) `4`=图像分片(`WTYICH1`magic+chunkNo+chunkTotal+totalBytes)。
`key-mode` 字节：`0`=Argon2id 口令 `1`=HKDF 会话密钥（32 字节）。

### 0.1 统一资源上限

`PayloadLimits.MAX_PAYLOAD_CHARS = 524288`（512 Ki 字符）。**WTY1–5 均在截取 Base64、解码或派生密钥前检查整个载荷长度**，包含五字符前缀和 Base64 填充。解码后必须至少包含完整 header 与 16 字节 GCM tag。WTY4/WTY5 的发送限制按同一预算计算，不能生成接收端因长度拒绝的载荷：

| 发送内容 | 最大明文字节数 |
|---|---:|
| WTY4 文本 / 整图 | 393157 |
| WTY4 图片页正文（另加 15 字节元数据） | 393142 |
| WTY4 图片分块正文（另加 19 字节元数据） | 393138 |
| WTY5 消息正文 | 393146 |

计算使用 `5 + 4 × ceil((headerBytes + plaintextBytes + 16) / 3) ≤ 524288`。文本先计数 UTF-8 字节，再分配编码缓冲；字节数不是字符数。超长正文必须在加密和棘轮推进前拒绝。二维码分片另有更小的传输上限，见第 6 节。

## 1. WTY3 envelope（兼容解密）

```
WTY3: + Base64( header(31) || AES-GCM-ciphertext )
header: [0]=0x03 [1]=type [2]=keymode [3..18]=salt(16) [19..30]=iv(12)
```
整 header 作 GCM AAD。keymode=0 → key=Argon2id(passphrase, salt)（历史固定 m=32MiB/t=3/p=1）；keymode=1 → key=HKDF(sessionKey, salt, info="WTY3-session-v1")。

## 2. WTY4 envelope（当前默认）

在 v3 基础上把 Argon2 参数写入 header，便于平滑调参。

```
WTY4: + Base64( header(37) || AES-GCM-ciphertext )
header: [0]=0x04 [1]=type [2]=keymode
        [3..6]=argon_memKB(uint32 BE) [7]=argon_iter [8]=argon_par
        [9..24]=salt(16) [25..36]=iv(12)
```
整 header 作 GCM AAD。默认 **m=64MiB / t=4 / p=1**。keymode=1 时 argon 字段填 0（用 HKDF，同 v3）。

**KDF 参数在 AEAD 验证前仍不可信，必须先检查预算，超出时拒绝，不得钳制参数后继续解密**：

- WTY4 接受 `memKB ∈ [8192, 65536]`、`iter ∈ [1,10]`、`par ∈ [1,4]`，且 `memKB × iter ≤ 262144`。这覆盖当前默认 64 MiB × 4 和正常旧消息；旧实现允许的 256 MiB 等超预算配置不再接受。
- JVM 实现中，所有 Argon2 调用（包括旧 WTY3）共用一把锁，整个派生过程串行执行，避免并发请求叠加内存。
- 分配前估算 `memKB × 1280 + 8 MiB` 字节，计入 Bouncy Castle 每个块的对象、数组及临时开销；估算不得超过最大堆的一半。
- 当前可用堆还必须容纳这笔估算和额外保留空间：`clamp(maxHeap / 4, 16 MiB, 64 MiB)`。余量不足时最多尝试一次 GC 并重新检查，仍不足则抛出普通安全异常。不会捕获 OOM 后继续，也不会自动降低 KDF 强度。

这些检查限制协议触发的资源消耗；应用同时持有大量图片等非 KDF 内存时，正常参数也可能被拒绝。WTY3 固定 `32 MiB / 3 / 1`、WTY4 默认 `64 MiB / 4 / 1` 的派生结果不变。

## 3. WTY5 — Double Ratchet（前向保密）

Signal 式双棘轮，适配无服务器/无握手/异步可乱序通道。用于已验证联系人的加密文本与二维码。

```
WTY5: + Base64( header(48) || AES-GCM-ciphertext )
header: [0..7]=epoch(int64 BE) [8..39]=发送方当前棘轮公钥(X25519, 32)
        [40..43]=PN(uint32 BE) [44..47]=N(uint32 BE)
```
整 header 作 GCM AAD。**消息无身份字段**——接收方对每个联系人非破坏性试解（见下）。

**会话 epoch（v0.6.1 起，header 由 40 → 48 字节）**：标识这条链源自哪一次自举，取值为自举方的 Unix 毫秒时间戳。

没有它时存在一个必然会发生的死锁：任一方重装 / 清数据 / 用备份码换机后本地棘轮状态丢失，会从**同一个确定性根密钥**重新开始，而对端根密钥早已推进——此后双向每条消息都 AEAD 失败且**永久无法恢复**，双方还无法把它与"消息损坏"区分开。唯一出路是两人同时删好友重加，而 UI 从未提示过这一点。epoch 把这个失败变成可判定、可自愈：

| 情况 | 行为 |
|---|---|
| `header.epoch == 本地 epoch` | 正常解密 |
| `header.epoch > 本地 epoch`，或本地无状态 | 判定为"对端重置"：按该 epoch 重新自举为接收方并试解，**仅当 AEAD 通过才落盘** |
| `header.epoch < 本地 epoch` | 拒绝。已退休会话的密文不得被重放进活会话 |

**初始根密钥**（双方确定性算出同值，复用已 SAS 核对的身份密钥；epoch 作 HKDF salt，故新 epoch 的根密钥与旧会话完全无关）：
`RK0 = HKDF(ECDH(身份A, 身份B), salt=epoch(8B BE), info="WTY5-root-init")`

**角色**：按 epoch 划分——开启某个 epoch 发送链的一方即该 epoch 的发送方，对端的初始棘轮密钥对 = 其身份密钥对（无 prekey 服务器的替代）。公钥字典序仅用于给**首个** epoch 定序，避免双方同时加好友时各开一个 epoch。任一方都可主动开新 epoch 恢复失步会话（实现必须提供"重置加密会话"入口，且必须说明旧消息将不可解）。在拿到发送链前可回退 WTY4，无 PFS，需对用户可见。

**根链 KDF**：`(RK', CK) = HKDF(ikm=DH_out, salt=RK, info="WTY5-root", 64B)` → 前 32B=新根密钥，后 32B=链密钥。

**对称链 KDF**：`messageKey = HMAC-SHA256(CK, 0x01)`；`CK' = HMAC-SHA256(CK, 0x02)`。

**消息密钥派生 (key+iv)**：`HKDF(ikm=messageKey, salt=0^32, info="WTY5-msg", 44B)` → 前 32B=AES key，后 12B=IV。只有正确完成下述并发控制与持久化，才能保证同一发送状态不被重复使用。

**DH 棘轮步**（收到新棘轮公钥时）：PN=Ns；Ns=Nr=0；用旧/新自有棘轮私钥分别与对端公钥 ECDH，两次根链推进得到新收链、新发链；并生成新棘轮密钥对。

**乱序/丢失**：header 带 PN（上一发送链长度）与 N（本链消息号）。跳过的消息密钥进有界缓存：单步上限 `MAX_SKIP=1000`，全局上限 `MAX_SKIP_TOTAL=2000`（按插入序淘汰最旧）。

**实现要求（安全关键）**：

- **decrypt 必须事务化**：在状态副本上运行，AEAD 认证通过后才提交；伪造消息不得改动状态。
- **锁必须覆盖整个读取 → 加解密 → 持久化操作**。桌面跨进程调用须共享稳定文件锁；Android 的身份/联系人变更与棘轮操作共享同一进程锁，不能仅锁加密函数。
- **发送方状态必须同步持久化后**才可发出密文，否则崩溃后重派生同一 (key,iv) 会造成 GCM nonce 复用。桌面使用同目录临时文件、文件同步和原子替换，在支持的 POSIX 文件系统上另同步目录；不支持原子替换或保存失败时拒绝输出密文。
- 会话须绑定本机与对端身份，更换任一身份不能沿用旧状态。Android 发送时还要在锁内重新核对当前身份、公钥和验证状态，拒绝已经失效的目标快照。
- 接收路由：对每个联系人加载状态、事务化试解，成功才提交该联系人状态。
- 换步/进链时清零被取代的旧根/链密钥。
- 按第 0.1 节限制收发长度；WTY5 发送端仅在完整封包生成成功后推进内存状态。

**桌面本地状态升级**：当前 `StoredRatchet` 在 `WTYRS1` 容器内保存双方公钥与序列化棘轮状态。这是本地存储格式，不改动 WTY5 线上载荷。旧未绑定身份的文件被拒绝使用：profile 先核对完整安全码并执行 `peer-verify`，再执行 `peer-reset --peer NAME`；原始 `--state FILE` 用对应身份与对方公钥执行 `ratchet-init`，再发送新消息。双方都需要升级旧状态时先各自重置，再由最后重置的一方先发消息；旧会话中尚未接收的消息可能无法解密。本地容器仍是明文，身份绑定不提供对恶意本地文件写入者的认证保护。

## 4. 身份码 WTYID1（二维码）

```
WTYID1|<name>|<base64url(publicKey 32B)>
```
name 去首尾空白、截断 40 字符、`|`→`/`、空则 "未命名"。

## 5. 备份码 WTYB1（用户手抄）

```
WTYB1- + Base32( publicKey(32) || privateKey(32) || CRC32(前64B)(4) ) 按 5 字符分组、'-' 连接
```
解码：剥离空白/NBSP/零宽/连字符 → Base32 解码 → 68 字节校验 CRC32 + 私钥导出公钥一致性；兼容 64 字节的 v0.4 旧备份（无 CRC）。

## 6. 多二维码分片 WTYP1

单张二维码 payload 上限约 800 字节；超出时按 800 字节切片，每片：
```
WTYP1|<id>|<N>|<T>|<chunk>
```
`id = Base32(SHA-256(完整payload)[..5]).take(8).lowercase()`。重组：按 N(1..T) 顺序拼接，校验 `id` 与重组结果一致，且重组结果 `isPayload()` 为真（含 WTY1-5）。可阻止跨消息分片拼接。

当前发送端每片正文最多 800 字符，总页数最多 32，因此一组二维码最多承载 25,600 字符的密文。此限制独立于 512 Ki 字符的协议上限；长度符合文本协议预算，并不意味着可以生成一组二维码。

## 7. 完整身份安全码（认证方案 v2）

`SafetyCode = HKDF-SHA256(ECDH(身份A,身份B), salt=排序拼接两公钥, info="WTY-SAS-v2", length=32B)` → 大写十六进制，共 **64 个字符**，每 4 字符一组，16 组以 ASCII 空格分隔。双方必须通过可信渠道核对全部字符。

旧 8 位数字没有交互密钥承诺，不能抵御攻击者同时搜索双方替换公钥的碰撞攻击，当前不再用于认证。`shortAuthString` 保留 API 名称，但输出以上完整安全码。认证记录携带 `authVersion=2`；旧验证状态需撤销后重新核对。Android 确认前锁内重算安全码；桌面 `.auth` 记录还绑定双方完整公钥。身份二维码、备份码及会话密钥派生不改变。

会话密钥（喂给 WTY3/WTY4 keymode=1）：`HKDF(ECDH, salt=排序拼接两公钥, info="WTY-session-v1", 32B)`。

## 8. 安全边界与限制

- **有 PFS**：已验证联系人的 WTY5 文本/二维码。
- **无 PFS**：共享密钥（WTY1-4 口令）、WTY4 会话密钥路径、WTY5 在 Bob 首次回复前发出的整个首发链（含长期身份成分，回复后完整生效）。
- WTY5 不做头部加密：棘轮公钥和计数器可见；密文不直接携带长期身份公钥，但聊天平台与传输元数据仍可能识别通信双方。
- **身份生命周期**：Android 更换身份（`replaceIdentity`）或恢复到**不同**身份时清空旧 ratchet 会话，联系人重置为未验证；恢复相同身份保留本机已有状态。身份备份本身不包含棘轮状态，换设备后仍需恢复会话。桌面 profile 更换本机身份或联系人公钥时清除对应旧状态，读取时检查双方身份绑定。
- **身份损坏恢复**：身份读取失败、长度错误或公私钥不匹配时拒绝使用，不静默生成替代身份。用户可显式恢复有效备份或生成新身份；联系人列表也不可读时，须通过明确的恢复/重建入口清空联系人和会话。恢复同一身份且数据可读时保留状态，显式丢弃不可读联系人时清空相关会话。
- **联系人迁移**：Android 首次导入未经认证的旧明文联系人 JSON 时清除 `verified`，要求重新核对 SAS；Keystore 中记录迁移标记，后续拒绝明文降级。升级认证方案 v2 时，已有加密列表中没有 `authVersion=2` 的验证标记也会清除，要求重新核对完整安全码。桌面无有效新版认证记录的联系人不得发送或重置，使用 `peer-verify --peer NAME --code FULL_CODE` 完成验证。
- **输入边界**：先在聊天框输入再加密无法阻止宿主预先读取明文。Android 的独立输入页可在交给聊天应用前加密，但所用输入法仍可读取内容；复制/分享进入文图易的文字也已经过来源应用。
- **解密结果来源**：Android 屏幕解密结果通过进程内、带请求标识的单次结果存储传递，不从外部广播接收明文或完成通知。
- 旧 WTY1/WTY2 的 `type` 字节未认证（无 AAD），仅类型混淆/DoS，非伪造；v3 起经 AAD 关闭。
- **接收生命周期**：已消费的 WTY5 消息不能重新计算明文。页面旋转和键盘输入会话切换保留当前请求的进程内结果；这不提供永久消息历史，进程结束后明文结果会消失。
- **重置 epoch**：`newEpoch(previousEpoch)` 取当前毫秒与 `previousEpoch + 1` 的较大值，严格大于已存状态；最大整数无法递增时拒绝重置。
- **CLI 正文**：stdin 待加密正文不 trim；密文/备份等协议输入仍允许首尾空白规范化。解密正文 stdout 不补换行，接入方必须完整保留内容。
- 无多设备同步。
